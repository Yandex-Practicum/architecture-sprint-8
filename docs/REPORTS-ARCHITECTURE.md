# Архитектура решения: подготовка и получение отчётов

## Компоненты

1. **Источники данных**
   - **CRM** — данные о клиентах (профиль, привязка к протезу).
   - **DB (телеметрия)** — данные с датчиков протезов (сырые события).

2. **Apache Airflow (ETL)**
   - **DAG** по расписанию (например, ежедневно):
     - Extract: чтение из CRM и из БД телеметрии.
     - Transform: группировка телеметрии по пользователям, объединение с данными CRM.
     - Load: запись в витрину отчётности в OLAP-БД.

3. **OLAP-БД (витрина)**
   - Отдельная таблица (витрина) для сервиса отчётов.
   - Структура оптимизирована для быстрого доступа по `user_id` и периоду.
   - Содержит только данные за периоды, уже обработанные Airflow.

4. **Reports API (бэкенд)**
   - Эндпоинт `GET /reports`: возвращает подготовленный отчёт по пользователю.
   - Читает данные только из OLAP-витрины (без тяжёлых вычислений в реальном времени).
   - Доступ: только свой отчёт (user_id из токена/сессии).

5. **Клиент (UI)**
   - Кнопка «Получить отчёт» → запрос к API через bionicpro-auth (с сессией).
   - Неавторизованный пользователь не может запросить отчёт; авторизованный — только свой.
