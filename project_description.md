## Задача 2. Разработать Airflow DAG и настроить его на запуск по расписанию.
Реализуйте ETL-процесс с использованием Airflow, который будет извлекать данные из CRM-системы и записывать их в базу OLAP.
Подготовьте витрину — отдельную таблицу для сервиса отчётов, в которой вам предстоит объединить данные телеметрии и данные о клиентах из CRM-системы. Для этого нужно будет сгруппировать аналитику по телеметрии в разрезе клиентов. Спроектируйте структуру витрины таким образом, чтобы обеспечить быстрый доступ к данным по пользователям. За основу при написании DAG можно взять материал уроков спринта.
Настройте расписание сбора данных и подготовки витрины.

### Решение
 - Разработан DAG: /airflow-data/dags/bionic_rag.py
   - состоит из 4х этапов: сбор данных БД bionic-crm (пользователи); сбор данных из БД api-db (данные об использовании протезов); их объединение по id пользователя и загрузка в clickhouse.
 - в docker-compose добавлены необходимые контейнеры^
   -  airflow (по примеру в уроках); 
   -  контейнер clickhouse с инициализацией схемы данных на docker volume
   -  в БД контейнера postgres хранятся данные обоих сервисов: и bionic-crm и api-db (намеренно упрощено по сравнению со схемой архитектуры). Данные заливаются при инициализации БД  
 - контейнер airflow-cli запускает (снимает с паузы) dag объединения данных (получается через раз)
 - в логику dag добавлены переменные таймстемпа данных, которые были захвачены при последнем запуске dag, поэтому только первый запуск dag фактически проведет работу по переливке данных.
