# Task 2

## Что сделал

В этом задании собрал отдельный контур отчетности:

1. Подготовил архитектуру с ETL через Airflow, витриной в OLAP БД и чтением готовых отчетов через API.
2. Добавил DAG, который забирает данные из CRM и телеметрии, агрегирует их и собирает витрину в ClickHouse.
3. Написал backend `/reports`, который отдает только отчеты текущего пользователя.
4. Доработал UI, чтобы можно было запросить отчет и скачать его в JSON.

## Файлы

- `task2/BionicPRO_C4_reports.drawio.xml` - диаграмма для решения по отчетам
- `airflow/dags/reports_etl.py` - DAG ETL
- `backend/app/main.py` - API `/reports`
- `backend/app/auth.py` - проверка JWT из Keycloak
- `frontend/src/components/ReportPage.tsx` - кнопка получения отчета и вывод данных
- `docker-compose.yaml` - инфраструктура для CRM, телеметрии, ClickHouse, Airflow и backend

## Как устроено решение

Логика такая:

- `CRM DB` хранит информацию о клиентах и протезах.
- `База данных` хранит телеметрию по работе протезов.
- `Airflow` по расписанию забирает данные из обоих источников.
- После этого Airflow собирает витрину в `OLAP БД отчетности` на базе ClickHouse.
- `API` читает уже готовые данные из ClickHouse, а не считает отчет на лету.
- `Приложение для донастройки протеза` вызывает `/reports` и получает только свой отчет.

## ETL и витрина

DAG находится в `airflow/dags/reports_etl.py`.

Что он делает:

- загружает клиентов и протезы из CRM в staging-таблицы ClickHouse
- агрегирует телеметрию по каждому протезу
- собирает итоговую витрину `reports_user_summary`

Расписание:

- DAG настроен на запуск каждый час: `0 * * * *`

Почему витрина подходит для быстрого чтения:

- отчет уже собран заранее
- API делает простой `SELECT` по пользователю
- в ClickHouse таблица упорядочена по `(keycloak_username, prosthesis_code)`

## API и ограничение доступа

В backend сделал `GET /reports`.

Как работает доступ:

- backend берет `preferred_username` из JWT токена
- по нему ищет строки в витрине `reports_user_summary`
- поэтому пользователь получает только свои данные
- доступ к чужим отчетам через параметр запроса не предусмотрен

## Что поменял в UI

Во фронтенде кнопка `Download Report` теперь:

- вызывает `/reports`
- показывает отчет на странице
- скачивает полученные данные как `bionicpro-report.json`

## Как проверять

1. Поднять проект:
   `docker compose up --build -d`
2. Открыть фронтенд:
   `http://localhost:3000`
3. Открыть Airflow:
   `http://localhost:8081`
4. Логин в Airflow для standalone:
   пользователь `admin`
   пароль смотрите в логах контейнера `airflow`
5. Убедиться, что DAG `reports_etl` существует.
6. Запустить DAG вручную, если не хочется ждать расписание:
   `docker compose exec airflow airflow dags trigger reports_etl`
7. Войти во фронтенд под пользователем Keycloak, например `prothetic1 / prothetic123`.
8. Нажать `Download Report`.
9. Проверить, что на странице появились данные и скачался JSON.

## Что именно стоит проверить руками

- в Airflow DAG выполняется без ошибок
- в ClickHouse появляется таблица `reports_user_summary`
- backend на `http://localhost:8000/health` отвечает `ok`
- `/reports` с токеном пользователя возвращает только его строки
- у разных пользователей приходят разные отчеты

## Что получилось проверить локально

Удалось проверить следующее:

- стек поднимается через `docker compose`
- backend отвечает на `/health`
- Airflow видит DAG `reports_etl`
- ручной запуск DAG завершается со статусом `success`
- после выполнения DAG в `reports_user_summary` появились 3 строки для тестовых пользователей `prothetic1`, `prothetic2`, `prothetic3`
