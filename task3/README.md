# Задание 3: Снижение нагрузки на базу данных с помощью кеширования отчетов в S3 и CDN

## Описание задачи

После внедрения фичи получения пользовательской отчетности нагрузка на OLAP-базу данных значительно возросла из-за частых запросов одинаковых отчетов. Поскольку данные обновляются ETL-процессом по расписанию, отчеты для одного пользователя не меняются между обновлениями.

**Цель:** Снизить нагрузку на OLAP-базу, исключив повторные запросы для уже сформированных отчетов, и разработать механизм сохранения отчетов в объектное хранилище S3 с раздачей через CDN.

## Решение

### Архитектура

- **OLAP база данных (PostgreSQL):** Хранит агрегированные данные в таблице `client_datamart` (client_id, name, email, total_events, last_event).
- **API сервис (FastAPI):** 
  - Аутентификация через Keycloak (JWT).
  - При запросе отчета проверяет наличие в S3.
  - Если отчет есть, возвращает CDN URL.
  - Если нет, генерирует из OLAP, загружает в S3, возвращает URL.
- **S3-совместимое хранилище (MinIO):** Хранит отчеты в бакете `reports` по пути `reports/{client_id}/report.json`.
- **CDN (Nginx):** Reverse proxy с кешированием статических файлов (TTL 10 мин для успешных ответов, 1 мин для 404).
- **ETL (Airflow):** Ежедневно обновляет данные, очищает кеш в S3 после обновления datamart.

### Механизмы

#### Кеширование и хранение отчетов
- **Структура хранения в S3:** `reports/{client_id}/report.json` — быстрый доступ по client_id (email).
- **CDN кеширование:** Nginx кеширует ответы от MinIO. Ключ кеша: `$scheme$proxy_host$request_uri`.
- **Обновление кеша:** После ETL (обновление datamart) задача `clear_s3_reports` удаляет все отчеты из S3. При следующем запросе отчет генерируется заново и загружается. Кеш инвалидируется косвенно: Nginx получает 404 и кеширует на 1 мин, затем обновляется на новый отчет.

#### Снижение нагрузки
- Первый запрос к отчету: Генерация из OLAP + загрузка в S3 (нагрузка на базу).
- Последующие запросы: Возврат CDN URL (без нагрузки на базу, кеш в CDN/S3).
- После обновления данных: Кеш очищается, отчеты пересоздаются.

### Компоненты

- **reports_api:** FastAPI сервис (порт 8083).
- **olap_db:** PostgreSQL для OLAP данных (порт 5435).
- **minio:** S3-хранилище (порт 9000).
- **nginx_cdn:** CDN proxy (порт 8084).
- **airflow:** ETL оркестратор (веб-интерфейс на 8082).
- **keycloak:** Аутентификация (порт 8080).
- **redis:** Кеш для телеметрии.
- **frontend:** React приложение (порт 3000).

### Запуск

1. **Сборка и запуск:**
   ```bash
   cd task3
   docker compose up --build -d
   ```

2. **Инициализация данных:**
   - Данные симулированы в ETL DAG (`etl_crm_telemetry`).
   - Запустите DAG вручную через Airflow UI (http://localhost:8082) или CLI.

3. **Тестирование:**
   - Получите токен в Keycloak (http://localhost:8080, realm: reports-realm).
   - Отправьте POST на http://localhost:8083/reports с заголовком `Authorization: Bearer <token>`.
   - Ответ: `{"report_url": "http://localhost:8084/reports/{client_id}/report.json"}`

### Конфигурация

- **S3:** MinIO, бакет `reports`, эндпоинт `http://minio:9000`.
- **CDN:** Nginx с proxy_cache (зона `cdn_cache`, max_size 1G, inactive 60m).
- **ETL:** Airflow DAG с расписанием `@daily`, зависимости: extract → load → create_datamart → clear_s3.


Это решение эффективно снижает нагрузку на OLAP-базу, обеспечивая быстрый доступ к отчетам через CDN.
